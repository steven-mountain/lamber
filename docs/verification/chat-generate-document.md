3. 从产品需求信息页清空“部署环境要求”并失焦，完成度10/11。页面原按钮仍可生成，聊天卡片也显示“仍缺：部署环境要求。仍可生成”。卡片再次生成成功。两份实际DOCX的50个文本节点逐个一致；按关系解析图片后，正文结构与图片位置/字节一致。原始XML仅有自动分配的图片关系ID及docPr编号差异，不是内容差异。
4. 暂时重命名合成测试附件1的物理文件，卡片9/11并说明缺图。点击生成显示产品原始alert `Error: 附件图片文件缺失，请重新上传后生成。`；确认alert后聊天出现相同原文的“文档未生成”回执。测试文件已恢复。
5. 请求立项签批表：卡片6/7，并明确“尚有1项未能判断：项目背景。不能确认整表已齐备”。真实模型读取工具后报告unknownCount=1，引导点击卡片，并说明不会代为生成、不会在回执前宣称已生成。

首次独立测试应用无Key，模型返回配置错误，但不影响用户卡片生成；后续真实模型验证以现有本机Key注入测试进程环境执行，未把凭据写入测试配置或日志。需求表真实回复明确“部署环境要求目前为空（缺项不阻止生成）”，并说明点击卡片后由系统执行既有流程，以回执为准。
