# 校验值与写入值一致性修复（2026-09-09）

对应 [独立任务书](../tasks/TASK_BOOK_validated_value_vs_written_value.md)。本修复单独记录，D 卡片整体验收另列。

## 实现

`ictTaxItemBatch.prepareIctTaxItemsInclBatch` 从原批量入口提取无副作用变换，保留原 `normalizeTaxPairFromIncl`、自动修正开关、拆分清除、CT 联动、资金计划同步及零值恢复/补建行为。`useIctState.updateTaxItemsInclBatch` 只在明确提交时调用它并设置状态；不再维护另一份金额变换。

结构候选先调用同一纯变换，按有效目标和承接金额算总额；偏差交给承接科目吸收，再归一一次。仍不闭合或出现负值，候选无效，不进入财务引擎求值。最终批量入口接收归一后的金额，因此候选另按这两个确切参数建立 CT 联动状态，避免收入和联动成本税率不同时再次不一致。科目计划与四组现金流均从有效候选重建。

搜索、最终总额检查及达标检查使用同一有效载荷；搜索期间固定自动修正设置，提交前若设置变化则拒绝重试。没有修改二分策略、采样策略、指标公式、`METRIC_EPSILON=0.0001` 或 `MONEY_EPSILON=0.004`，没有改写用户目标。

甄选限价回填不属于可补差的结构池。预演真实批量归一后，若目标科目或单列服务费任一金额改变，则在两个自动修正分支均明确拒绝；不默默更改确认过的限价/服务费。关闭自动修正时原不可表示检查仍保留，去掉“开启自动修正即可”的误导性建议。
