## 已确认的失败路径

- `IctLifecycle.tsx` 的含税输入 `onChange` 直接执行 `Number(e.target.value)`；输入中间态空字符串变成 0。
- `syncSubjectFundingPlanToAmount` 收到 0 就删除原计划；再次输入正金额，缺失计划会自动创建首年一次性计划。
- 试算只收到最终覆盖值 800000，因此调用共用编辑函数时原四年计划仍在，按原规则同比缩放。
- 使用**抽取前桌面源码 fixture**分别执行“106000→800000”与“106000→0→800000”，同样重现四年计划与首年计划的分叉；所以不是本轮抽取改变了规则。

证据：[原桌面输入过程复现](./ai-benefit-clear-input-diagnosis.json)、[逐项桌面读数及差异](./ai-benefit-desktop-evidence.json)。

**此前建议（已被新任务书方案 1 替代）**：先修桌面编辑中间态，将“暂时清空输入”与“正式提交金额为 0”区分。编辑中保留原资金计划，正式确认 0 时再按原规则处理；之后重新执行 B 的完整桌面对照。没有擅自实施该调整，也没有让 B 模拟错误的计划重置。
