## 任务书示例的算术更正

本轮用独立 Python Decimal 和 Rust 生产函数逐步交叉核对，发现原任务书两个示例数值不自洽，不能为了通过示例而更改确定的费率：

| 步骤 | 正确值 |
| --- | --- |
| 含税报价 | 300000.00 |
| 除以 1.06 | 283018.8679245283… |
| 乘 0.00809985 | 2292.41037735849… |
| 不含税服务费先舍入 | 2292.41 |
| 再乘 1.06 | 2429.9546 |
| 含税服务费再舍入 | 2429.95 |
| 浮动 0 时含税限价 | **302429.95** |

原书中的 2292.42 / 2429.97 / 302429.97 是算术笔误。此外，106000.01 + 858.59 = **106858.60**，不是 106858.59。固定 6% 下报价按分计时，106424.00 与 106858.60 之间的限价（先扣含税浮动）没有对应报价。

在 12100、48500 两个不含税档位边界还存在很小的向下跳变，因此整张表并非单调、一一映射。反算对各档的整分报价分别二分搜索，只接受正算精确闭合的结果；无解返回错误，少量多解返回全部候选（最多各档一个），选较低报价并在界面说明。用户可切回正算指定原报价。不能承诺在多解处唯一恢复原始报价；测试证明原报价在候选集合中且每个返回值正算闭合。

## 真实历史项目只读对照

只读检查用户已有工作区快照，找到一份历史报价 88500、浮动 1000、锚点 quote 的样例；旧快照中实际成本 88900、服务费 400、限价 89900。将同一组辅助输入在上述独立测试应用重放后，新值为 88924、424、89924。拆分目标仍为 89500，服务费增加 24 元。真实项目没有打开写入、没有保存、没有迁移；不会因本次代码更新自动重写正式科目。

历史变化要按锚点和档位分别解释：固定报价时，目标报价+浮动不变，服务费与限价更新；固定限价时，限价保持，报价和服务费由新表反算。不能把所有比例档简单描述成原金额再加 6%：报价现在也先除税，部分比例档的税率会抵消，仍以逐步舍入结果为准。
