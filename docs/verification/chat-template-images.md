# 聊天查看及替换需求表图片（2026-09-10）

用户明确同意补齐“展示已有图片 → 选中具体图片 → 新旧预览 → 确认替换”的流程。本轮完成需求导入表attach1/attach2的查看、替换与发送视觉分析；用户于2026-09-10明确排除AI裁剪、改字及生成式修图，不属于未完成事项或后续待办。未开放通用文件工具，未修改测算。

## 实现与边界

- 聊天“项目图片”按钮或本轮明确展示/替换图片请求打开卡片。读取可信会话绑定项目的资产，不依赖主窗口当前项目、是否打开模板或是否已保存第一份表单；普通图片聊天、否定与引用不会自动开启。
- 卡片列出已有需求表附件，可逐张选择、预览完整图、将选中图加入输入框，用户发送后模型才获得图片字节。普通聊天附件不自动存入模板。
- 选择/粘贴新图只在内存中生成候选并显示新旧对照，取消不写入。用户点击确认才调用专用IPC；该命令没有注册成AI工具。后端核对会话、工作区、项目、模板、原资产存活状态和附件槽位。
- 复用原资产保存函数，在同一SQLite事务中插入新图和软删除原图。新图保留原created_at以维持附件顺序；其他图片不动。保存或删除失败回滚，新图已落盘则清理新文件，旧文件保留。旧卡片重复提交在保存前拒绝。
- 前端校验PNG/JPEG/WEBP、20MB、非空并实际解码；后端补查MIME签名、大小和正尺寸，不声称后端具备完整图像解码器。视觉发送仍受原模型图片大小限制。
- 保存后通过既有附件事件刷新页面，发起会话收到文件名、尺寸、资产编号的前后回执，卡片保留前后两图。通知失败报告“已保存但刷新失败”，不诱导再次写入。
- 图片卡片暴露了原scrollIntoView会滚动外层窗口的问题，自动滚动改为只设置消息列表scrollTop，限定flex高度且不压缩卡片。实际重开、滚动、文件选择及预览后输入框保持可见。

“项目图片”只查看/替换已有图。无旧图时仍走独立缺图上传卡片或模板页；初次真实模型曾错误说此卡片可新增，已补充明确边界并真实复验。普通上传仍是追加，不能宣称覆盖。其他模板及询价截图不加入本轮替换能力。
