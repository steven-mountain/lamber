# AI 按钮离屏窗口恢复验证（2026-09-07）

## 原因与证据

用户在`tauri dev`主页点击右下角AI按钮，报告“完全没反应，没有新窗口”。入口可见，显示偏好不是问题。只读检查开发版WebKit的三个限定键，旧AI窗口位置分别为`{x:419,y:-802}`、`{x:539,y:-957}`；系统当前只连接内置Color LCD。独立测试应用也保留`{x:305,y:-911}`。

原`AiFloatingLauncher`创建窗口时直接传入保存的逻辑坐标；复用现有窗口时只show/setFocus。两条路径均不检查窗口是否位于当前显示器，`preventOverflow`创建选项不能替代运行时位置恢复。原生错误只写控制台，表现与点击无反应相同。

## 有界修复

- `aiAssistantWindow.ts`统一新建和复用：等待原生created/error、合并重复点击、unminimize、按当前显示器workArea核验、调整位置及必要的尺寸、show/focus。
- 新窗口不将未经校验的旧坐标传给构造器；窗口准备好后以物理像素统一校验。合法负坐标显示器仍保留，不使用简单的`x/y >= 0`判定。
- 位置保存为带version=2的物理像素；旧逻辑坐标在创建时转换并核验，不清空用户位置偏好来掩盖错误。
- 失败在入口旁显示并可重试；不删除窗口会话或业务数据。仅增加窗口位置/尺寸/恢复最小化的Tauri UI权限。

## 已验证

- 前端lint/build通过；保留既有大bundle提示。
- `test:ai-window`执行生产几何函数和窗口服务：两组现场负坐标、有效屏内位置、负坐标外接屏、过大窗口、无效缓存、物理坐标不重复缩放、最小化复用、创建事件顺序、并发点击只创建一次、创建及show失败后重试、监听清理。
- 独立macOS Scope Test应用构建通过。
- Computer Use：保留测试应用`y=-911`，从主页点击AI入口，实际出现AI工作区、会话列表和输入框；截图可见整个浮窗。关闭后位置记录为`{version:2,x:690,y:152}`，说明恢复并保存了可见位置。
- 正在运行的开发版随前端及能力配置变更重新加载。已请用户在原窗口复验，尚未收到回复。

## 限制

Computer Use首次打开与关闭已通过，随后再次打开前电脑锁屏，未将重开界面检查记为通过；创建/复用/重复点击行为有自动回归。真实外接屏拔插、不同DPI组合及Windows桌面未实测，不冒充该平台验收。本轮不涉及模型调用或业务数据修改。
