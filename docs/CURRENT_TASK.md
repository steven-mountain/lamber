# 智算金额来源另存、导入导出与同步明细修复

- **Status:** Done
- **Objective:** 支持将当前智算画布另存为普通金额来源，支持当前金额来源 JSON 导入导出，并修复 ICT 同步明细状态列过窄导致行高异常的问题。

## Progress

1. [x] 新增智算金额来源交换包格式 `lamber.intelligentCompute.amountSource` v1，导出当前来源的参数、公式、收入/成本项、资金计划、映射和项目周期/折现率。
2. [x] 导出包剥离 `projectId`、`sourceVersion`、同步快照和 H200 基准保护标记，避免跨项目导入时携带旧身份或受控状态。
3. [x] 后端新增金额来源导出/读取 IPC，复用 Tauri dialog 选择文件，并在 Rust 侧校验 kind/schema/核心数组字段。
4. [x] 智算页面新增“另存为来源”“导出当前来源”“导入来源”，导入前展示来源名、当前项目参数和文件参数，默认允许用户确认后覆盖周期/折现率。
5. [x] 另存为来源使用当前内存画布生成新普通来源，不先覆盖原来源；自动保存回调在执行时重新检查保存状态，避免排队保存误写旧来源。
6. [x] 导入来源生成新来源 ID、清理旧同步状态并设为当前唯一 ICT 同步来源，后续仍走现有同步与 0 容差校验。
7. [x] ICT 同步明细弹窗改为固定表格布局，扩大弹窗宽度并给“来源项”“状态”列设置稳定宽度，避免状态文本单字换行。
8. [x] 更新智算专项测试、Rust 交换包校验测试、模块文档、外观约束和 AI 变更日志。

## Validation

- `npm run test:ai-compute-quote --prefix src-ui`
- `npm run build --prefix src-ui`
- `cargo test`
- `git diff --check`

## Scope Boundary

- 不改变 ICT 正式计算公式、现金流、NPV、税率、甄选费、资金计划 0 容差校验或文档生成口径。
- 导入导出范围仅限当前金额来源，不做全部来源或完整项目迁移。
- 导入来源不直接写入 ICT 正式测算；只有用户后续同步确认或自动同步通过既有校验后才更新 ICT。
