视觉以**当前固定版本的 dsh 官方 WebUI**为全产品基准：AI与主应用复用或映射其组件、语义 token、圆角层级、字体尺度、间距和交互状态。Lamber保留品牌、中文业务语义与财务tabular numbers；旧Architectural Ledger、ROUND_FOUR及独立蓝灰配色不再作为目标规范。[DESIGN.md](../../DESIGN.md)是新的全局规范，[appearance.md](../modules/appearance.md)记录迁移规则和旧实现。不能反向重画官方组件以迁就旧风格。

宽屏可同时阅读会话列表和正文；窄窗可收起侧栏，输入区及确认按钮始终可达。长表格在自身区域滚动，长文审批在窄窗改为上下对照。深浅主题、现有字号缩放、高 DPI 下不能裁切文字、遮挡输入或产生页面级横向溢出。协议、会话 ID、插件树等诊断放到按需查看的位置。

### 3.1 视觉一致性整改（用户截图反馈，待实施）

**目标：新增业务能力看起来属于 dsh 原生界面。** 覆盖项目选择/绑定、业务工具入口、全部业务面板、审批、设置、历史和操作回执；不能只修首页按钮，也不能以“功能能用、没有溢出”替代视觉验收。

#### 已见问题与源码依据

- 用户截图中，官方输入框和图标按钮具有明显圆角；项目绑定及六个业务按钮却组成较方正的灰底/蓝底块，视觉重量与周边不一致。
- 绑定信息和六个等重按钮挤在输入框上方，与左侧目录入口的对齐、间距不统一；目录名称与绑定项目名称不同，界面又缺少清楚的语义区分。此处仅确认展示存在歧义，不能据截图推断实际权限绑定错误。
- 收起的侧栏使用图标，新增“历史”却显示为实心矩形文字按钮并折成两行，样式和占位均不匹配。
- `src-ui/src/ai/webui/style.css` 为 surface、按钮、面板等硬编码 `4px`，并在 `.lamber-business` 设 `--radius: 4px`；`src-ui/tailwind.config.js` 的 `rounded-sm` 使用 `calc(var(--radius) - 4px)`，在该作用域得到 `0px`。这是局部圆角退化的明确路径，不应再用一个全局 radius 覆盖所有控件。
- 同一 CSS 一部分使用 `--dsw-alias-*`，另一部分重新定义浅/深蓝灰 HSL 色板，造成两套 surface 并存；`LegacyHistory.tsx` 的入口为裸文字 button，未按官方侧栏按钮呈现。
- `client.tsx`、`BusinessWorkspace.tsx`、`LegacyHistory.tsx`、`style.css` 与 `scripts/build-webui-client.mjs` 是相关入口。生成的 `agent-bridge/webui/lamber-brand/lib/client.js` 必须由源码构建，不直接修改产物或上游 node_modules。

#### 统一规则与布局方向

| 项目 | 必须达到的结果 |
| --- | --- |
| 圆角 | 对照官方同类控件分别映射图标按钮、普通按钮、输入/选择、卡片、浮层的圆角；优先官方组件或 token。没有公开 token 时依据固定版本实测集中定义适配值并记录来源，禁止一律 4px、一律大圆角或算成 0px |
| 色彩与层级 | 以官方背景、悬浮层、控件、文字和强调色语义为单一来源；清除业务区平行调色板。普通工具入口保持次要层级，主色用于当前主要动作或选中态；hover/focus/disabled/error 与官方协调 |
| 项目上下文 | 显示清楚的“目录/工作区”与“绑定项目”语义，在同一内容网格对齐；已绑定态用紧凑状态呈现，未绑定态保留明确选择入口。不合并两种身份、不根据名称擅自改绑 |
| 业务入口 | 默认采用一个轻量“项目工具”入口展开菜单/面板，六项能力完整保留、最多一次展开可见；需要常驻的高频快捷项使用同一官方按钮样式。取消常驻整块灰底承载六个等重实心按钮的布局，业务菜单避开输入和发送操作 |
| 侧栏 | 收起态的“旧会话记录”采用与相邻官方图标同尺寸、同对齐、同命中区的图标按钮，提供 tooltip 与无障碍名称；展开态按官方结构显示横排文案，不允许“历/史”竖排。与日常会话列表含义区分 |
| 业务面板 | 标题/关闭按钮、表单、主次操作、列表/表格、错误反馈与官方弹层对照。圆角嵌套、内容留白、行高统一；采用官方浮层/焦点机制或等价受控实现，不重做业务保存链 |
| 字体与图标 | 字号/字重/行高跟随官方同层级文字，保留已接入字体与数值等宽要求；图标风格、线宽、按钮尺寸协调，不能用单字代替图标或固定字号抵消用户缩放 |
| 响应式 | 按官方正文与输入区域对齐，不靠绝对定位或负 margin 对截图凑位置；长项目名、窄窗、侧栏切换时布局仍成立，菜单/面板不裁切、不遮住必要操作 |

#### 实施顺序与修复边界

1. 在同版本、同主题、同字号与相同视口下，记录官方按钮、输入、菜单、侧栏及浮层的基准样式与计算值；列出扩展区对应差异。当前截图作为问题依据，不据截图像素猜 CSS 尺寸。
2. 建立全产品共享的设计token与基础组件映射，分别适配WebUI扩展和主应用承载；先改AI项目上下文、工具入口与历史入口，随后应用到业务面板、审批、设置及回执。原业务组件复用逻辑；不能为少改代码复制更多颜色/圆角常量，或为两个窗口建立两套视觉值。
3. 清理导致冲突的局部 HSL 常量、裸按钮、错误圆角计算和重复覆盖；确保 Tailwind 产物和官方 CSS 的作用域、优先级可解释。禁止为修扩展区全局覆盖官方 button/input，或把官方圆角压成直角。
4. 品牌调整限于标识、名称和必要文案；官方欢迎区、输入框、消息布局保持视觉基准角色。主应用页面按第3.2节向同一基准迁移，保留业务信息结构、可读性与财务数值精度，不新增高饱和背景。
5. 本整改只处理展示、布局和必要的菜单/浮层交互，不变更工具权限、审批决定、项目身份、财务计算、保存/生成动作、历史恢复及回执去重语义。

## 4. 架构与迁移原则

1. **完整复用官方 WebUI 及配套会话/连接机制。** Lamber 管理桌面承载与进程生命周期，业务插件连接现有服务。具体采用本地 web 服务或受控桌面传输，在阶段 0 实跑后选定并记录依据，不提前承诺某种载体零改造可用。
2. **插件优先，扩展范围明确。** 前端扩展负责项目入口、业务卡片、审批呈现、主题；后端扩展负责可信身份、上下文、业务服务适配。不要直接改 `node_modules`，不要通过 DOM 文案选择器拼装核心功能。发现官方接口不足时先记录最小缺口、方案及影响，不默默引入整套上游分叉。
3. **状态归属唯一。** 新活动会话的消息、流、工具过程由 dsh 体系管理；Rust 继续拥有业务授权和审计；Lamber 只保存必要的绑定、迁移标记及业务回执。前端可以有缓存和草稿，但不能长期双写两个独立聊天历史源。
4. **身份与工作区严格对应。** WebUI 新建、恢复、复制/分支等任何可用会话入口都必须纳入绑定规则。由后端登记可信 dsh 会话身份；模型参数和前端显示项目不得改变权限。项目绑定不可改绑；通用会话沿用当前实际工具白名单，不能退化成无权限会话或扩大数据访问。
5. **业务动作复用原服务。** 保留现有 Rust 引擎、前端共享金额变换、编辑器联动及生成入口。不要为了 UI 迁移把所有数学移到 Rust、插件或模型中，也不要复制一套求解/生成实现。
6. **一条审批决定链。** 复用当前业务审批校验、实际旧值、修改后文本、两版审计、绝对截止时间和失败拒绝语义；官方与 Lamber 不能同时独立回答同一审批。无承载窗口、超时、关闭、陈旧输入和重复确认不能放行或重复写。
7. **业务交互有稳定身份。** 卡片请求与回执关联会话、动作和业务目标；回执可恢复且进入正确会话的模型上下文。历史回放、重新渲染、重连不得重执行写入。陈旧的预览/批准令牌不能因恢复界面重新有效；完成动作即使卡片关闭也保留真实回执。
8. **设置归属统一。** 本轮优先保留 Lamber 当前配置持久化，通过新版设置适配；明确全局默认与单会话模型选择的生效范围，避免 WebUI 与原设置中心各写一套冲突配置。密钥不回显、不写聊天历史，不因换 UI 宣称新增任意 OpenAI-compatible 兼容性。
9. **桌面权限和分发一起落实。** 本地资源、请求来源、原生 IPC 和后端工具权限需明确边界，不能给完整网页开放任意 Tauri 命令。若用回环服务，由应用管理地址/端口、访问校验和退出清理；不得暴露业务桥接令牌给模型。沿用关闭遥测、工具白名单及工作区校验；隐藏按钮不代替后端限制。
10. **收敛旧代码。** 每个旧职责建立“新接替者／保留理由／删除条件”清单。ACP 显示适配、旧消息投影、旧聊天组件在接替并验收后退出产品调用链；诊断入口如保留需有明确用途。不要为保留旧协议而模拟整套官方服务；过渡开关仅用于迁移验证，不成为长期双 UI。

## 5. 业务保真要求

- 模板文本：保留新旧对照、编辑后批准、覆盖/填空规则、模板版本与工作区复核、冲突处理；以实际批准内容写入。
- 文档生成：沿用原生成入口、保存态表单组装、缺项/unknown 口径及 0 容差核验。模型只触发邀请，用户点击后执行；失败保留原错误，成功才报告真实产物。
- 技术清单与询价：完整迁入当前显式采用建议、逐行编辑、共用字段提示、预览、保存与回执流程，不改变字段目录和完成度算法。
- 图片：保留需求导入表 attach1/attach2 的查看、用户选图、新旧对照、取消零写、确认事务替换和显式视觉附件。**不新增 AI 裁剪、改字或生成式修图**。
- A/B/C：只读/假设态标识、全部科目及逐年金额、税额口径、甄选费无解与多解错误沿用原结果，不在渲染层补算数值。
- D：单独迁移验收。选科目/指标 → 原函数范围 → 用户确认目标 → 原编辑器执行；目标不能因接近结果而改写。保留目标/实际四位百分数、全部科目和受影响 10 年计划前后对照、完整范围错误。范围内不等于离散目标可达，提交前使用实际将写入的归一状态及原容差判定；失败零写。确认修改编辑器，正式保存仍需原用户动作。
- 所有金额、税额、现金流、NPV、选费及反算规则保持；本轮不把业务缺陷修复混入 UI 替换。如发现影响迁移的真实缺陷，记录证据与受影响范围，先说明再确定修复范围。
