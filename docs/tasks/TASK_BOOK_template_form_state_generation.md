# 任务书：文档生成读取已挂载 DOM，导致非当前 tab 字段静默退回默认值

> **优先级：建议插在 `TASK_BOOK_dsh_full_integration.md` 阶段 3B 之前。**
> 3B 是"翻开关 + 删旧代码"，可以等；本文是**财务审批文件里静默出现错误内容**，不该等。
> 两者互不依赖，谁先做都不影响对方。

> **2026-09-06已修复并完成四模板跨页产物对照**：[验证记录](../verification/template-state-and-chat-assets.md)。

## 症状

同一份已保存的表单，从「生成确认」页点"立即生成文件"，生成的文档里
非确认页的字段退回默认值；从字段所在的那一页直接生成则正确。

阶段 3A 试用实测（`docs/verification/dsh-stage3a-streaming-and-handover.md`）：
需求导入表从确认页生成，需求单位退回 `XXX分公司`、服务内容退回默认组合，
而项目名和预算正常。留样：`3A/ICT项目需求导入表-3A流式验收项目-生成确认页留样.docx`。

**与 dsh / AI 无关**，是既有问题；阶段 3A 未修改 `TemplateForms.tsx` 或文档引擎。

## 已确认的关键事实（写代码前不用重新调研）

### 1. 根因：生成时读的是 DOM，不是保存态

`TemplateForms.handleGenerate` 用 `new FormData(formRef.current)` 取值，
只能取到**当前已挂载**的表单控件。

### 2. 所有 tab 都是条件渲染 —— 切走即卸载

`TemplateForms.tsx` 共 11 处 `{xxxTab === "..." && (...)}`（`:2189`、`:2272`、`:2428`、
`:2628`、`:2689`、`:2713`、`:2839`、`:2863`、`:3230`、`:3254`、`:3476`），
不是 CSS 隐藏。切到确认页时，其它页的 `<input>` 已从 DOM 移除，
`FormData` 读到空值，随后走默认值分支。

### 3. 波及四个模板，会审纪要最严重

| 模板 | tab 结构 | 从确认页生成会丢 |
| --- | --- | --- |
| 售前方案会审纪要 | basic / content / business / risk / confirm | **四个 tab 的字段** |
| 立项签批表 | content / confirm | content 全部 |
| 甄选结果签批表 | content / confirm | content 全部 |
| 需求导入表 | content / confirm | content 全部（已实测） |

**只修需求导入表那两个字段是不够的**，这是四份模板共用一条失败路径。

### 4. 完全静默，且完成度清单会给出反向信号

`getFormValue(name, default) = formData[name] ?? default`（`TemplateForms.tsx:1967`）
读的是**保存态对象**，而四张完成度清单（`demandCompletionItems` 等，`:2028` 附近）
用的正是它。

于是出现最糟的组合：**进度条显示 11/11 全部填写完整，生成的文档却是默认值。**
用户没有任何提示。而「生成确认」这个 tab 名本身就在引导用户在那里点生成。

### 5. 数据没丢，只是没被读到

已保存的 SQLite `formData` 里自定义字段仍在；回到字段所在页能看到正确值，
在该页生成也正确。所以这是**取值路径**的问题，不是保存或持久化的问题——
不要往保存链路上找原因。

## 要做的事

1. **把生成输入改为由统一的表单状态构造**，不再依赖当前挂载的 DOM。
   保存链路已经有一份权威的 `formData`，生成应当与保存读同一个源。
2. **四个模板一起改**，不是只改需求导入表。改完逐个模板从确认页生成一次做对照。
3. **加一道防呆**：生成时若发现某个必填字段在保存态里有值、而构造出的生成输入为空
   （或等于默认值），应当阻断并提示，而不是静默填默认值。
   这条是为了防止将来再出现同类取值路径分歧时又变成静默错误。
4. 顺带核对 `handleGenerate` 里是否还有其它同样依赖 DOM 挂载的读取
   （图片、动态行表格 `TABLE_*`、询价供应商行等），一并纳入。

## 不要做的事

- **不要只给出问题的那两个字段加默认值分支**——这是阶段 3A 记录里明确点名反对的做法，
  它把系统性取值路径问题伪装成局部缺省值问题，下一个字段还会再犯。
- **不要改 tab 为 CSS 隐藏来"保住 DOM"**。那样确实能让 `FormData` 读到值，
  但等于用渲染策略给取值路径打补丁，四张大表全量常驻还会带来性能与表单状态问题。
  正确的方向是让生成不再依赖 DOM。
- 不改 `docfill.rs`、模板变量映射、Word/Excel 生成引擎——问题在取值，不在填充。
- 不改财务计算、税额、0 容差校验、甄选费逻辑。
- 不改保存链路和 SQLite 结构——数据是好的（关键事实 5）。
- 不在本次顺手重构 `TemplateForms.tsx` 的整体结构。它很大，但本次范围是取值路径。

## 验证要求

1. **四个模板 × 两条路径**：每个模板分别"从字段所在页生成"和"从确认页生成"，
   产物文本逐字段比对，必须一致。会审纪要要覆盖 basic / content / business / risk 四页。
2. 用**非默认值**做测试数据。若测试数据恰好等于默认值，这个 bug 验不出来——
   阶段 3A 能发现它，正是因为填了"合成测试分公司"而不是"XXX分公司"。
3. 防呆分支（要做的事第 3 条）单独验一次：构造一个保存态有值但生成输入为空的情况，
   确认被阻断而不是静默生成。
4. 回归：确认现有的完成度清单、常用资料、项目预设、甄选批量等既有功能未受影响。
5. `npm run lint --prefix src-ui`、`npm run build --prefix src-ui`、
   相关 `npm run test:*`、`cargo test` 全过。
6. 结果记入 `docs/verification/`，并在 `docs/CURRENT_TASK.md` 标注本问题已修复；
   阶段 3A 验证记录里"生成确认页的字段问题单独待修"那句可回填修复链接。
