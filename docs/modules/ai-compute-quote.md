# 智算报价测算模块

## 定位

智算报价测算是 ICT 生命周期测算之前的业务报价蓝图模块。它负责维护报价参数、收入项、成本项、结构化公式、ICT 科目映射、业务项资金计划和单变量敏感性输入。

ICT 是正式科目、产权、现金流和效益指标的数据源；项目周期和折现率由智算稳定参数统一控制。智算不复制毛利率、NPV、IRR 或回收期算法；业务编辑停止 `500ms` 后自动同步到已有 ICT 正式状态并调用相同的 Rust 计算引擎。

## 数据与持久化

- 内置蓝图：`H200 标准智算报价蓝图`。
- 项目级保存键：`ai_compute_quote::active`。
- 蓝图持久化版本为 `4`。`parameterGroups` 保存类别稳定 ID、名称、说明、内置标识和显示顺序；参数的 `groupId`、`isKey` 与参数数组顺序分别保存归属、关键标记和同类顺序。
- 旧蓝图加载时自动把 `scale / price / cost / technical / finance` 迁移为规模、定价、投入、运营、财务；无法识别的参数进入“未分类”。
- 持久化复用 `project_settings` 的 `get_project_setting` / `save_project_setting` 命令，不新增数据库表。
- 自由预览模式不持久化；选择 Workspace 项目后才能保存。
- 蓝图修改实时重算；正式同步事务同时保存完整蓝图、revision、ICT 状态、现金流和正式效益结果。
- 蓝图 `syncState` 保存最近 revision、同步状态、时间、错误和每个联动 ICT 科目的最近提交快照。
- 行项目 `formulaControlStatus` 区分公式控制、ICT 人工覆盖和多来源合并冲突。

## 计算规则

- 公式使用可持久化 Token 序列，不使用 Excel 单元格坐标，也不执行 `eval`。
- Token 支持参数引用、计算项引用、固定值、`+ - * /`、左右括号、逗号和 `SUM()`。
- 引用通过参数/计算项内部 ID 绑定，名称仅用于页面显示，因此重命名不会破坏公式关系。
- `formulaEngine.ts` 使用递归下降解析器处理运算优先级、括号和函数，并区分 `valid`、`incomplete`、`error` 状态。
- 计算项依赖由 `calculations.ts` 构建依赖图并按依赖顺序求值。修改参数或上游计算项后，所有下游项目实时重算。
- 循环引用只标记循环相关计算项；依赖失败向下游返回明确错误，不影响无关项目。
- 缺失参数、缺失计算项、非法固定值和除零均返回显式错误。被引用计算项禁用时按 `0` 参与计算并显示提示。
- 旧版 `type + operands` 公式会在加载或首次编辑时转换为 Version 2 Token 公式，现有项目和 H200 蓝图保持兼容。
- 行项目金额以元为内部口径，页面金额汇总统一显示万元并明确标注。
- 含税金额由公式产生，不含税金额按 `含税 / (1 + 税率 / 100)` 计算。
- 总收入、总成本保留智算含税报价汇总；毛利率、NPV、净现值率、IRR 和回收期直接展示 ICT Rust 引擎返回值，效益结论区展示 ICT 毛利率、NPV、项目净现值率和动态回收期。
- H200 资金成本公式使用 `SUM({机器成本}, {维保成本}, {组网成本}) × {资金成本率} × 0.01`，因此页面参数仍按 `10%` 显示为 `10`。

## 折叠式计算器

- 每个收入/成本项默认使用统一摘要卡，只显示启用状态、名称、税率、含税/不含税金额、占比、ICT 同步状态、资金计划状态、公式摘要和展开按钮。
- 摘要层不直接展示名称、税率、ICT 映射、公式或年度金额编辑控件；删除操作也归入展开后的项目编辑。
- 向下展开后仅显示“项目编辑 / 计算公式 / 资金计划”三个 Tab，不保留总览或独立 ICT 同步 Tab。
- 项目编辑 Tab 维护名称、税率、ICT 同步科目、是否参与测算和是否参与 ICT 自动同步。
- 计算公式 Tab 可插入参数、其他收入/成本计算结果、固定值、运算符、括号、`SUM(` 和逗号，并支持回退、清空、单个 Token 删除。
- 资金计划 Tab 维护计划启用、第一年度一次性、平均分年、自定义年度金额、年度输入、计划合计、科目金额和差异校验。
- 公式 Token 之间存在 `N+1` 个可点击插入位置。当前插入点显示为主色竖线，点击 Token 会将插入点移动到该 Token 之后。
- 所有插入操作均写入当前插入点；插入后光标移动到新内容之后。“回退”删除光标前一个 Token，而不是固定删除公式末尾。
- 展开区实时显示业务名称公式预览、计算结果或明确错误原因。
- 计算项展开/收起和详情 Tab 状态是组件本地状态，不写入蓝图、项目 setting 或计算输入，因此不会影响计算结果。

## 四 Tab 测算工作台

- 顶部采用两行 compact header：第一行提供返回、标题、重新同步、保存蓝图和更多菜单；第二行集中当前项目、当前蓝图、ICT 状态、资金计划来源和保存状态。
- 主编辑区分为“参数区 / 收入计算项 / 成本计算项 / 敏感性分析”四个 Tab，徽标展示对象数量；敏感性分析作为独立分析工具，不再堆叠在参数区底部。
- 参数类别是蓝图业务配置。默认提供规模、定价、投入、运营、财务和未分类，用户可新增、重命名和排序类别。
- 内置类别允许重命名和排序但不可删除；自定义类别只有清空参数后才可删除。
- 默认“仅看关键参数”展示业务关键项；切换“全部参数”可查看全部类别与参数，不再使用“更多参数 / 高级参数”折叠区。
- 参数筛选支持关键、已修改、敏感性和全部模式；搜索同时匹配中文名称、字段 key 和单位。
- 规模、定价、投入默认展开为紧凑值卡；运营和财务默认折叠为单行参数摘要，可按需展开。
- 参数卡仅突出中文名、当前值、单位和默认/修改状态；字段 key、类别、关键标记、敏感性开关、排序、复制与删除收进次级设置菜单。
- 参数说明在当前卡片内按需展开，显示影响提示与收入/成本引用摘要，不占用固定侧栏。
- “全部参数”且搜索为空时可用原生拖拽调整类别顺序、参数同类顺序或跨类别移动；筛选/搜索时禁用拖拽，类别选择和上移/下移菜单继续可用。
- 参数区“新增”菜单可新增参数或类别；类别标题的“+ 参数”会预选当前类别。
- 收入和成本项使用一致摘要结构与轻量占比进度条；收入采用低饱和绿/蓝语义，成本采用低饱和橙/红语义。
- 页面右侧为约 `292px` 的固定只读效益结论栏，分组展示结论状态、核心金额、正式 ICT 指标、主要收入/成本和输出操作，不承担编辑功能。
- Tab、筛选、搜索、参数说明展开、计算项展开和详情 Tab 状态均为本地 UI 状态，不进入蓝图持久化或计算输入。
- 主布局使用 `minmax(0, 1fr)` 保护编辑区，窄屏时结论栏转到主区域下方；页面不得产生横向溢出。

## 输出包

- 每个收入/成本项最多映射一个 ICT 标准科目。
- 多个智算项可以映射到同一 ICT 科目，输出包按 `side + subjectCode` 合并。
- 禁用行、关闭输出的行、未映射行不进入输出包。
- 科目候选直接复用 `ictSubjectCatalog.ts`。
- 页面读取当前正式 lifecycle/cashflow 作为同步基底，按 `side + ictSubjectCode` 合并金额、税率、年度计划和来源项。
- lifecycle 输入允许兼容旧版或早期智算写入的不完整快照；同步适配器会从项目记录、profile、parameters、payment model 和 assumptions 重建完整 Rust `IctInput` 必填字段及全部标准科目，成功提交后用完整输入自修复持久化状态。
- 修改停止 `500ms` 后自动覆盖联动科目的含税金额、推导税率、不含税金额和 10 年计划；未映射科目及 ICT 财务参数保持原值。
- 禁用、关闭输出、公式异常或计划不一致的已映射项按 `0` 同步，避免 ICT 残留旧金额；错误仅影响相关科目。
- 自动同步比较当前映射与最近成功快照。取消映射、删除业务项或改映射到其他科目时，原 ICT 科目以 `released_mapping` 记录清零金额和 10 年计划；若原科目仍有其他智算来源，则只写入剩余来源合计。
- 历史项目若缺少原科目 `syncState.subjects` 快照，同步器会从 ICT 科目资金计划恢复旧控制关系。仅采信同项目、同蓝图、同场景且仍保持 `ai_compute_quote_import` 状态的导入痕迹；已人工维护或已归零的科目不会被兜底释放。
- 该释放规则基于完整 `ICT_SUBJECT_DEFINITIONS` 科目目录执行，不区分甲供材料、维护费、施工、其他投入或收入类科目；任意智算业务项改映射时均写入新科目并释放不再受控的旧科目。
- 智算 `years` 参数是项目周期唯一数据源，固定为不可删除、不可复制、不可改 key 的 1-10 年整数。
- 智算 `discount-rate / discount_rate` 是项目折现率唯一参数，页面按百分数输入，例如 `5` 表示 ICT 正式值 `0.05`；参数限制为 `0-100%`，不可删除、复制或改 key。
- 项目周期和折现率同步覆盖 ICT lifecycle、cashflow assumptions、正式 Rust 输入及项目汇总字段。Version 1-3 蓝图升级到 Version 4 时，从项目当前正式折现率强制初始化一次；之后以智算值优先。
- 导入记录包含 `source: ai_compute_quote`、`projectId`、`scenarioId`、`blueprintId`、来源行项目 ID 和导入时间。
- 导入审计分别保存当前受控 `ictSubjectCodes` 与本次清理的 `releasedSubjectCodes`。
- `sync_ai_compute_quote_to_ict` 先调用现有 `calculate_ict_benefit`，再在同一 SQLite 事务中提交蓝图、lifecycle、cashflow、metrics 和项目汇总。
- 每次提交校验 expected revision；过期请求返回冲突，前端合并最新联动状态后重试。
- 从智算进入 ICT 时，ICT 顶部返回入口显示“返回智算报价”，并保留项目 ID 与场景 ID。

## 业务项资金计划

- 每个收入/成本项持久化独立的 `fundingPlan`，包含启用状态、`first_year / even / manual` 模式和固定 10 年 `yearlyAmounts`。
- 旧蓝图缺少计划字段时，计算归一化会补齐启用中的第一年一次性计划，兼容既有 H200 蓝图和项目 setting。
- `first_year` 将当前行项目含税金额放入第 1 年；`even` 按项目周期平均分摊，周期限制在 1-10 年并把分级尾差并入最后一年；周期外年份保持 0。
- `manual` 保留用户逐年输入。用户修改任一年度金额时自动切换为该模式，允许计划合计与行项目金额不一致，并只显示提示而不阻止保存。
- 公式或金额变化后，`first_year` 和 `even` 自动按新含税金额重新生成；项目周期变化只重新生成 `even`，`first_year` 和 `manual` 不被改成平均分年。
- 每个行项目的资金计划只在展开区“资金计划”Tab 中展示，不再维护第二层独立折叠状态。
- 年度输出按 `side + ictSubjectCode` 合并，同一年金额相加并保留来源行项目 ID。
- “查看同步明细”展示金额、计划模式、有效项目周期、10 年合并计划、来源项、释放旧映射及暂停覆盖/冲突状态。

## ICT 人工修改反写

- ICT 保存联动科目时，以最近同步快照比较金额、税率和年度计划。
- 单一来源项发生变化时，智算写入 `ictOverride`，原公式保留但停止控制金额，并显示“已被 ICT 人工修改，当前公式失效”。
- 多个智算项合并到同一科目时不做自动拆分；所有来源项标记 `merge_conflict`，该科目暂停智算覆盖，其他科目继续同步。
- 用户逐项点击“恢复公式控制”后清除覆盖状态，下一次自动同步重新以公式结果覆盖 ICT。
- 用户主动修改或取消该业务项的 ICT 映射时，也视为重新交由智算控制并清除现有覆盖/冲突状态。
- 本阶段不把 ICT 项目周期、折现率、金额或计划持续反写为智算参数和业务项计划；旧项目仅在首次补充缺失折现率参数时读取当前项目值。

## 敏感性分析

- 支持选择一个允许敏感性分析的参数。
- 按最小值、最大值和正步长生成最多 500 组临时结果。
- 候选参数通过克隆蓝图构造相同的 ICT 输入，并调用批量 ICT 计算命令。
- 展示 ICT 毛利率、NPV 和净现值率；旧异步结果通过请求序号丢弃，不修改当前蓝图参数。

## 后续联动边界

智算只生产业务项结果和映射增量。共享 ICT 输入构建器与 Rust `calculate_ict_benefit` 是正式计算入口；禁止在智算侧新增另一套正式财务公式。
