# 智算测算与金额来源模块

## 定位与边界

智算测算负责维护计算参数、收入项、支出项、年度金额、ICT 科目映射和计算快照，并输出可确认的 ICT 科目增量。ICT 测算负责承接已确认的金额和年度计划，调用现有 Rust 引擎生成正式指标。

- 智算数据属于智算项目，不由 ICT 页面反向管理。
- ICT 人工修改不会改变智算公式或金额来源；下一次智算同步预览会展示将覆盖的差异。
- 项目周期和折现率是项目级智算状态，计算时只读注入每个金额来源。
- 行项目资金计划是年度金额的唯一来源，不保存第二份年度总额。

## 项目类型

公开项目类型为 `ict | intelligent_compute`，持久化在 `projects.project_type` 和 `project.json.projectType`。

- 新建项目默认 ICT，用户可选择智算。
- ICT 转智算时创建一个启用的 H200 标准金额来源。
- 智算转 ICT 时保留智算表和已同步 ICT 数据，只隐藏智算入口。
- 项目看板中 ICT 项目只显示 ICT 测算；智算项目同时显示智算测算和 ICT 测算。
- 智算页面只加载当前 Workspace 内且类型为 `intelligent_compute` 的项目。

## 持久化

schema v7 新增：

- `project_intelligent_compute_states`：项目周期、折现率、活动来源、状态版本、聚合同步 revision、受控 ICT 科目和最近正式结果。
- `intelligent_compute_amount_sources`：名称、启用状态、参数、收入项、支出项、映射、计算快照和来源版本。

历史 `project_settings.ai_compute_quote::active` 在 v6→v7 时迁移：

- 对应项目标记为智算项目。
- 原蓝图名称、参数、公式行项目、资金计划、映射、同步 revision 和科目快照迁入首个金额来源。
- 旧 setting 保留只读；新 store 和同步命令不再写入。

## 金额来源

每个智算项目至少保留一个金额来源；同一时间只有一个当前金额来源参与 ICT 同步。

- 新增空白来源仅保留项目级周期/折现率参数，不预置收入、支出和映射。
- 新建来源必须命名，可选择空白、H200 标准、当前来源或任一已有来源作为基底。
- 复制已有来源会复制参数、公式、资金计划、映射和计算方法；新建后自动成为当前唯一 ICT 同步来源。
- 来源选择同时决定编辑对象和 ICT 同步来源，避免两个 H200 来源同时参与导致金额翻倍。
- 来源支持选择、重命名和删除；最后一个来源不可删除。
- 来源保存使用 `sourceVersion` 乐观锁；项目级状态使用 `stateVersion` 乐观锁。
- 现有 `AiComputeQuoteBlueprint` 仅作为单个来源的前端计算适配模型，不再代表项目级持久化对象。

## 计算与校验

- 公式仍使用可持久化 Token 和递归下降解析器，不执行 `eval`。
- 收入/支出依赖按内部 ID 排序计算；循环引用、缺失引用和除零返回明确错误。
- 历史 `ict_override / merge_conflict` 字段可被反序列化，但不再覆盖或阻断智算公式。
- 已启用、已映射且参与输出的行项目必须公式有效、资金计划启用且年度合计与含税金额达到分级 0 容差。
- 未映射、已停用或关闭输出的行项目仅提示并跳过。

## 自动与显式同步

同步流程：

1. 智算参数、公式、资金计划、映射或当前来源选择变更后，页面先防抖保存当前金额来源，再自动调用 `sync_intelligent_compute_to_ict` 写入正式 ICT 状态并刷新右侧效益指标。
2. 自动同步使用业务指纹去重：只关注当前同步来源、项目周期、折现率、参数、公式、资金计划和映射；来源名称、描述和版本号变化不单独触发 ICT 写入。
3. 手动“同步到 ICT / 查看同步明细”仍保留，用于查看覆盖/释放预览和失败后手动重试。
4. 同步只读取当前选中的金额来源；同一来源内多个行项目映射到同一 ICT 科目时，按 `side + ictSubjectCode` 汇总含税金额、不含税金额与 10 年计划，税率由汇总含税/不含税金额反算。
5. 当前来源未产出的所有 ICT 标准收入/成本科目写入金额 0、年度计划全 0，并使用科目默认税率；旧受控科目生成 `released_mapping` 以便审计。
6. 后端在同一事务中校验项目类型、聚合 revision、完整来源集合和每个 `sourceVersion`，运行 Rust 正式计算并更新 lifecycle、cashflow、项目汇总和智算同步快照。
7. 遇到同步 revision、来源集合或来源版本冲突时，前端阻塞旧预览写入，提供“重新加载冲突并覆盖”入口；重载最新状态后再执行智算完全覆盖 ICT。

ICT 标准收入/成本科目的金额、税率和资金计划由智算完全覆盖；产权、现金流模型和其他非智算金额参数沿用当前正式状态。同步请求只提交来源 revision 和同步输出，不提交可由 ICT 管理的智算编辑状态。

金额口径：

- 智算与 ICT 同步统一使用“元、含税”作为业务金额口径，万元只用于页面展示。
- ICT 标准科目目录维护 `defaultTaxRate`，空科目保留标准默认税率，不再写成 `0%`。
- 同步 payload 同时写入含税、不含税和税率，正式现金流仍由 `ictCalculationInput.ts` 和 Rust 计算引擎生成。

导入痕迹使用：

- `source: intelligent_compute`
- `amountSourceIds`
- `sourceLineItems: [{ amountSourceId, lineItemId }]`

旧 `blueprintId / scenarioId / sourceLineItemIds` 继续兼容读取。

## 导航与状态隔离

智算进入 ICT 使用显式 `IctOrigin`，包含 Workspace ID、智算项目 ID、项目名称和活动金额来源 ID。

- 仅当来源 Workspace、项目 ID 和项目类型均匹配时，ICT 顶部显示“来源：智算项目 …”和“返回智算测算”。
- 直接打开 ICT 不显示智算返回入口。
- 切换 ICT 项目、切换 Workspace 或返回项目看板会清除来源。
- 智算加载和 ICT hydration 使用请求代次校验；发起新加载时先重置完整模块状态，旧响应不得覆盖新项目。

## 正式计算边界

智算只生产业务金额、年度计划和映射增量。`ictCalculationInput.ts` 与 Rust `calculate_ict_benefit` 仍是正式现金流和效益指标入口；禁止在智算侧复制 NPV、IRR、税务、甄选费或反算公式。
