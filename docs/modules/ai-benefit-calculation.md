# AI 测算只读接入（A/B/C）

**当前状态：清零误删计划已按新任务书修复，B 桌面手工输入的全部效益指标已逐项对齐；年度转述及真实 key 回归也已通过。详见 [验证记录](../verification/ai-benefit-calculation-access.md)。**

A/B/C 的只读工具不提供 AI 回填金额、保存试算或创建方案入口。D 通过下述用户操作卡片独立接入，不增加 AI 反算工具。

## 工具与口径

- `read_benefit_inputs`：会话绑定项目的最新已保存快照，返回 28 科目（9 收入、19 支出）、中文目录名、自定义/开票名、拆分明细、六组合计及总计、资金计划与现金流假设。共享 `ictSubjects.json` 目录，金额用 Rust Decimal 合计，坏数字报错。税率是百分数（6 = 6%）。
- `run_benefit_calculation`：`basis=saved_snapshot`，重放已保存输入。A/B 与它共用 `calculation::resolve_snapshot`；阶段 → id → 名称，无法匹配明确报错，缺省使用默认方案/最新方案。
- `simulate_benefit_calculation`：只接受 `scenario?` 与具名 `overrides`，不能传入项目 id 或整份输入。`basis=hypothetical`；显式覆盖与联动变化分别展示，始终提示未保存。
- `calculate_selection_fee` / `reverse_calculate_selection_fee`：纯计算白名单，可信通用会话也允许。路由直接调用原 Rust 命令，不复制档位、舍入、反算或数值校验。报价/限价/浮动含税，服务费同时显示含税与不含税；展示四位计费基数；多解列全部候选并说明选择低报价，无解与坏输入原样报错。新工具不消费旧 `selection_fee` 字段。
- 系统未计算 IRR。工具必须说明这一事实；`query_projects` 收到 IRR 筛选/排序直接报错，不能伪装成零匹配。

## B 的同一条桌面联动路径

`ictTaxItemEdit.ts` 从原 `useIctState.updateTaxItem` 抽出纯变换，桌面编辑与试算共同调用：税额换算、拆分清除、CT 产品→其他产品成本/专线→带宽成本、资金计划金额同步。`serializeTaxItemForPayload` 也由桌面与试算共用。不修改 `updateTaxItemsInclBatch`、甄选费回填、反算搜索或原引擎公式。

Rust 验证会话与方案，复制快照，创建一次性内存任务，只向 `main` 窗口发 opaque id。主窗口通过两个限制 window label 的 Tauri 命令领取和交还任务，用当前主窗口的财务自动修正偏好执行纯函数，不读/改当前编辑器、导航、dirty 状态、数据库或方案。状态管理必须使用应用已注册的 `Arc<AgentRuntime>`。

任务仅能领取一次，失败/超时后移除，迟到回执不能匹配后续任务。等待不持有工作区/数据库锁。返回前再次核验绑定、工作区、选中方案及最新快照；变化则拒绝。所有指标来自同一次原 Rust 引擎调用。

只读试算的当前支持边界：

- 非空覆盖要求快照有完整有效的科目资金计划，且保存的四组年度税前现金流与计划一致。按原计划比例同步并重建；不把缺计划的历史方案猜成首年付款。
- 重建后校验资金计划覆盖及四组现金流与对应科目不含税合计，拆分无效或尾差不一致明确拒绝，不返回“新利润率 + 旧 NPV”。
- 启用总额锁定/差额承接、重复/未知科目、同时覆盖 CT 联动的一对科目，明确拒绝；不搬运 D 的结构反算逻辑。
- 金额使用无单位非负数字字符串、最多 2 位小数、上限 10^12 元；税率 0–100，最多 6 位小数。这是 B 内存编辑边界，不应用于 C。
- `overrides=[]` 原样重放快照（包括旧方案），不修改数组，指标与已保存重算一致；`taxInclAutoFix=null` 表示没有执行金额编辑。

## 金额归零与年度转述

资金计划同步在金额归零时清零并停用计划，保留最近有效分布；连续清空不丢备份，再次正数恢复原模式并记录 `restored_after_zero`。正式零值不产生现金流，重载后仍可恢复。补建策略不变，不推测或迁移历史已丢失计划。详见 [专项验证](../verification/funding-plan-zero-delete.md)。

保存态/假设态共用逐年结果渲染；年度联动变化以每年覆盖前/后完整金额输出，其他变更保留完整原始字段。工具及会话约束禁止用乘年数、省略号或末尾小数代替不相等的年度金额。原始字段始终保留，不在渲染层重算或舍入。模型不得自行补算差额、均值或尾差金额；真实模型测试检查表格和附注的小数均有工具字段来源。


## D：用户确认的结构反算卡片（2026-09-09）

- `structureReverseIntent` 只依据本轮用户请求邀请卡片；否定、历史回顾和税率数字不能预填目标。无数字留空，目标科目每次重选，不持久化。
- 顺序固定为选科目/指标 → 原函数只读采样范围 → 用户确认目标 → 原编辑器执行。`previewOnly` 复用原搜索的前置检查和采样，不另建求解器。
- `chatStructureReverse` 经主窗口 IPC 打开绑定项目的所选方案；选择器沿用阶段、精确 ID、最新同名语义，匹配不到即拒绝。单次预览令牌绑定会话/工作区/项目/方案/科目/指标和编辑器输入，过期或变化必须重读；不自动重试写入。
- `IctLifecycle` 在写前再次检查身份与输入；执行原 `performReverseCalculation`，写后等待当前编辑器指标就绪，核对 28 科目、四组现金流和达成值。候选与真实批量入口共用有效状态变换，详见 `ict-structure-reverse.md`。
- 结果固定并排展示四位百分数的目标/实际，卡片自身沿用 `METRIC_EPSILON=0.0001` 核对。逐科目含税金额及受影响收付款计划前后表覆盖全部 10 年；不是旧 model_e 分板块。
- 所有原错误完整进入聊天 `appReceipt` 和后续模型上下文，四条范围错误不得压缩。模型逐字引用原错误、目标/实际、金额/年度尾差；只读说明不能修改目标或自动写金额。
- 确认仅修改当前编辑器；用户再走原保存入口。卡片关闭后已完成的写操作仍产生历史回执。
