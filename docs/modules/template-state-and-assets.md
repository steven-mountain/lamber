前端完整解码后预览；后端拒绝空图、伪造MIME签名、超限和无效尺寸。保存完成后发送原附件变更事件和带具体前后信息的发起会话回执；通知失败仍明确已保存。聊天自动滚动限定消息容器，图片卡片不压缩或滚动外层窗口。

该卡片无新增；缺图用原上传卡片/页面。用户于2026-09-10明确排除AI修图：保留图片展示、视觉分析和用户确认替换，不增加AI裁剪、改字或生成式图像编辑，也不列为后续待办。普通上传是追加，替换仅影响用户确认的那张。元数据不代表已看见像素；不得猜路径或调用通用文件工具。[验证](../verification/chat-template-images.md)。

## 生成输入

四类分标签模板（会审纪要、立项签批、甄选结果签批、需求导入）和普通模板共用
`templateGenerationState.ts` 的字段构造器。生成与 AI 草稿上下文不再读取 DOM FormData。

- `formDataRef.current` 是普通输入字段的当前保存源；默认值取共享目录，显式空字符串不被目录覆盖。
- 项目规模、自主三问、商务模式、资金来源和收付款条款由各自业务状态负责，优先于历史 `gen_*` 副本，确保常用资料/项目预设直接更新状态时生效。
- 动态技术明细、询价供应商、批次模型仍沿用原状态和计算逻辑。
- 生成前逐项核验有值的原始字段，输入丢失或退回其他值时阻断。复选框支持历史 `true` 与 `on`；取消选中保存显式空值。
- 标签页只决定展示，不决定生成内容。禁止恢复 DOM 读取或依赖常驻隐藏控件。

## 共享缺项规则

`lib/templateCompletion/demand.ts` 接收序列化表单状态及可选资产列表，输出固定11项，包含字段/图片类型、模板名称、usage。
模板页完成度、AI 正式上下文的 completion 和聊天补图卡片均调用这一份规则。

AI 上下文按 SQLite 已保存状态计算；未保存草稿仍单独标识，不冒充正式状态。
缺项资产须实际存在；缺失物理文件不能计为已完成。需求分析意图可以在当前项目中定位工作区唯一需求表模板，模板不唯一则提示选择，不能猜测。

## 附件所有权与同步

仅需求表 `attach1` / `attach2` 改为以未软删除的资产记录为准。旧无 assetId 的图片保留迁移支持，已迁移图片不再由陈旧表单引用覆盖。

- 聊天卡片固定可信会话绑定及缺项条目给出的 sessionId / workspaceId / projectId / templateName / usage，用户选择文件或粘贴才调用既有 `save_template_asset`。普通聊天图片不自动入库。
- PNG / JPEG / WEBP，20MB 上限；文件读取/解码、工作区复核完成后再写。选择过程中切换会话或工作区会拒绝写入。
- 卡片显示目标项目、模板和槽位；回执读取实际路径，不假定绑定项目目录。写入已成功而路径查询失败时明确说明已入库，避免诱导重复上传。
- 上传/移除发出 `lamber-demand-assets-changed`。主窗仅刷新对应模板图片，不重载或覆盖正文草稿；刷新序号及目标身份隔离迟到响应。
- 模板重新进入时重新读取资产，生成时再次读取资产快照，避免事件迟到导致漏图。软删除失败时不假装从界面移除成功。
- 后台孤儿清理保留本项目未删除的需求表两槽资产，防止模板页未打开、尚无表单引用时误删聊天上传。已删除资产、其他模板和其他项目不受这条保护影响。
- 系统回执在流式回答结束后追加到发起会话，避免抢占当前 assistant 流的更新目标。

以上附件流程不新增业务工具、SQL 接口、表或 migration，不修改审批机制、财务计算或 Word/Excel 图片映射。

## 阶段 B 文本保存与同步（2026-09-07）

11项完成度定义移至 catalog.json 的需求表分组；默认值、完成度、Rust 文本白名单与插件字段 schema 使用同一源。工具与 UI 复用 save_template_state_locked，并使用已有 template_version 做保存冲突检查。

批准文本按目标和版本广播，模板页进行三方合并；同字段草稿冲突时停止自动保存并允许查看草稿、显式放弃后重载。保存串行化，生成前先保存并阻断未解决冲突；载入采用身份/序号检查，避免延时回填或旧请求串页。完整设计见 [ai-template-write.md](./ai-template-write.md)。

### 主动读取与规则复用

read_template_fields 读取绑定项目保存态及资产存在标志；插件构建直接编译 demand.ts 纯函数，避免Rust重写缺项逻辑。截断文本与完整缺项标志分开传输，最终工具结果不暴露内部投影或本机路径。页面注入与保存链路不变。[验证](../verification/template-read.md)。

### 字段目录泛化（2026-09-07）

需求表兼容入口和立项页面共同调用catalog.ts纯函数；动态默认值/项目背景由页面既有业务状态提供。读工具只依据保存态，外部派生/校验值未知时明确标注，不复制测算或校验算法。收付款按目录stateKey对原根状态做审批取值、提交和前端三方合并；同字段草稿冲突仍阻断旧副本保存。[目录设计与边界](../../src-ui/src/lib/templateCompletion/README.md)。

### 聊天上传卡片独立数据通道（2026-09-07，补充二）

**触发口径修正：绑定项目只是数据归属，不代表填表意图。** `demandFormIntent.ts` 从当前会话最后一条用户消息识别直接填写/输入或生成需求导入表的请求；匹配采取保守规则，提到表名、只读查询、否定、引用和助手话术不会自动开启。卡片仅在“本轮明确请求 + 可信项目绑定 + 共享规则缺图”时出现，意图条件放在组件挂载之前，未触发时不读取卡片业务数据。不同说法不能确定时保持安静，用户可明确说“帮我生成需求导入表”或“我会输入需求导入表”。

意图不另存为跨轮开关，不因历史的一次请求永久催上传；助手流式回复/工具回执保持本轮条件，新的普通聊天、取消、只读问题或纯聊天图片使卡片退出。切回会话按该会话最后的用户消息恢复，清空后无卡片。本轮模型提示复用相同判定，不能凭绑定或读工具发现缺项主动催图。这是 UI 邀请，不授予写入或生成权限。

`demandUploadTargets.ts` 按后端会话绑定读取 `list_template_states` / `get_template_state` / `list_template_assets`，通过既有资产路径读取检查实际存在状态。直接调用 `getCatalogCompletion`，仅取 `kind=image && evaluated && !filled`，槽位 `usage` 从条目原样传递。卡片不依赖 `buildAiChatContext`、页面 activeTemplateId 或模型调用结果，也不将读取的表单加入 prompt。

优先按绑定项目已保存的需求模板逐一显示明确名称；无保存态时仅接受配置目录中唯一需求模板，多个未保存候选提示先明确目标，不猜文件名。附件2仍遵守共享目录的公示网址条件。

`DemandImageCompletionCards` 集中管理读取和刷新，单张卡片只负责一个确定槽位的用户上传。会话身份作为 React key，异步读取有失效清理；附件事件、批准文本事件、窗口聚焦和消息数量变化触发刷新，工作区事件立即清除旧目标。写前重新读取绑定和工作区，并检查组件是否仍属于活动会话。读取失败提供重试，不把失败当成已补齐。

系统提示与读工具说明只描述产品能力：用户在聊天卡片选图/粘贴会调用原资产保存命令；模型没有图片写工具，普通聊天附图不自动存库。补齐后卡片消失，实际写入结果仍由发起会话的系统回执确认。[验证](../verification/demand-upload-decoupling.md)。

## 聊天生成文档（2026-09-08，方案 B）

`DocumentGenerationCards` 按本轮明确的具名模板生成请求挂载。目标来自后端可信会话绑定和当前配置目录，不依赖模板页或 AI 上下文；需求表、立项签批、甄选结果签批复用 `getCatalogCompletion`。`evaluated=false` 单列未知项，不算缺项或已齐备；缺项不禁用生成按钮。只读检查、绑定会话或普通聊天不会自动展示生成卡片。

`chatDocumentGeneration.ts` 仅传递用户点击的目标身份和请求ID，不承载变量映射。发送端先订阅结果，主窗口确认接收后进入 loading → opening → generating → running；接收前过期的请求不再执行，已接收请求不以定时器替代项目/模板/测算就绪，也不自动重试。主窗口串行处理，重复点击不创建第二次生成。跨项目导航复用未保存提示；进入模板复用 `handleTabSwitch` 的覆盖、科目收付款计划、阶段及0容差检查。

项目和模板分别报告加载完成；测算报告对应输入指纹及错误，旧异步结果不得覆盖新结果。生成等待当前项目输入对应的测算结果，防止自动入口抢在手工页面通常等待的计算之前执行。该修改只整理计算生命周期，不改变财务公式。

页面按钮与卡片统一调用 `runUserGeneration → handleGenerate`。变量构造、原保存事务、资产加载、甄选批量校验、后端引擎、覆盖确认和生成成功提示保持单一实现；handleGenerate 额外返回结构化结果，原 alert 文本同时用于失败回执。执行前再次核对目标和可信绑定；尚未发出后端生成时切项目/方案/模板会取消，已经发出的生成等待真实结果，不伪称撤销了落盘。成功回执使用后端实际返回目录，按请求发起会话追加，不抢占流式回答。

焦点与内容刷新保留当前卡片 DOM，避免用户点击先触发窗口focus而卸载按钮；只有工作区变更、读取失败或目标身份变化时清除旧目标。AI没有生成工具，不直接调用generate_lifecycle_docs；用户点击本身是生成确认，不新增审批弹窗。验证见[聊天生成卡片](../verification/chat-generate-document.md)。

## 聊天技术清单与询价卡片（2026-09-08）

两张独立组件按本轮意图及可信会话绑定挂载，不要求模板页打开。`chatTemplateLists`只通过产品读取通道取得明确目标和当前列表；实际写入沿聊天文档请求协议唤起主窗口原项目/方案/模板加载，再运行原模板状态拥有者。页面载入、绑定、列表期望快照、模板版本都要匹配，旧卡片不覆盖新列表。异步失败只标记原目标冲突，不污染切换后的模板。

`TechItemsCard`允许采用本轮AI四列表格建议、增删改后保存。页面虽共享一份techItems状态，数据库却每模板各自保存；单写当前表再切换会恢复另一表旧值。卡片因此明示来源和所有保存目标，UI保存命令可传sharedTechTemplates，后端在同一事务中核对各模板原列表后调用原保存主体，原子更新所选及共用模板。冲突或损坏状态整体回滚，其他字段、询价、映射、输出配置和资产保持各自所有权。该参数不开放给Agent桥接，不增加AI清单写工具。

`InquiryCard`只在用户确认后调用模板页唯一autoGenerateInquiry；原随机报价和三条前置检查保持原实现。结果在下一次React提交后经原保存串行器持久化，再回传实际行。生成器失败返回原错误，保留原列表。用户修改金额调用原handleInquiryAmountChange封顶；截图使用原资产保存及vendor_N槽位，保存后展示实际资产。卡片无增删报价行或替换已有证据功能，重新生成保留截图的规则也沿原页面，并提示重新核对截图。

应用卡片回执标记appReceipt后写入发起会话；dsh不拥有这些本地事件，故下一轮按会话选择最近8条作为只读上下文，保持发生顺序，区分历史成功与最近失败。模型输出不带该标记，不按正文关键词识别“成功”。此规则同时适用于图片、文档和两张清单卡片。
