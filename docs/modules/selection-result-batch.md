# 多项目甄选结果签批表模块设计

本模块把多个已完成甄选的 ICT 项目按业务数据汇总为一份《ICT项目甄选结果签批表（50万以下）》。合并发生在结构化数据层，最终只调用一次现有 DOCX 模板填充引擎；不拼接多个 Word 文件。

## 入口与文件职责

- `src-ui/src/views/TemplateForms.tsx`：多项目选择、排序、批次字段、冲突提示、续签归类、预览和生成拦截。
- `src-ui/src/services/selectionResultBatchService.ts`：只读加载候选项目、甄选前/后方案、方案工作副本、快照和模板资料。
- `src-ui/src/lib/selectionResultBatch.ts`：数据恢复、校验、金额口径、冲突检测和 A-E 五表模型构造。该模块不调用 IPC，便于独立测试。
- `src-tauri/src/docfill.rs`：继续使用通用 `TABLE_*` 模板行克隆和占位符替换，不引入甄选表专用生成分支。

## 候选项目与数据来源

多项目候选仅包含 `project_type = ict` 且同时存在以下两类已标注方案的项目：

- 最新甄选前方案 `stage = pre_selection`；
- 最新甄选后方案 `stage = post_selection`。

同阶段存在多套方案时按 `updated_at` 取最新一套。读取每套方案时优先使用按 `(project_id, scheme_id)` 保存的 lifecycle/cashflow 工作副本；无工作副本时回落到该方案最新快照。批量模式只读取已保存状态，不读取其他项目尚未保存的 React 草稿，也不写回项目。

## 五张表的取数规则

所有表均按用户设置的项目顺序排列；项目序号在 A-E 表中保持一致。同一项目有多个科目时，仅首行显示项目序号和名称。

| 表 | 内容 | 数据来源 |
| --- | --- | --- |
| A | 甄选最高限价 | 项目手填甄选限价优先；未填写时取甄选前方案全部 IT 投入 |
| B | 中选报价 | 甄选后方案全部 IT 投入 |
| C | 项目投入 | 甄选后方案全部投入科目 |
| D | 项目收入 | 甄选后方案全部收入科目 |
| E | 效益指标 | 甄选后方案项目净现值率、项目毛利率、IT 净现值率 |

金额使用 `decimal.js` 累加并统一输出两位小数。A、B、C、D 的合计分别独立计算；特别是项目收入不得复制项目投入合计。

## 立项金额口径

批次立项金额为不含税金额：

`全部 IT 投入 + CT 专线建设 + CT 专线维护 + CT 专线带宽成本 + 经确认属于专线的续签成本`

以下项目成本不计入立项金额，但仍按其真实业务科目出现在 C 表投入明细中：

- CT 其他产品成本；
- 非 IT/CT 成本；
- 综合类成本；
- 经用户确认属于其他产品的续签成本。

`cost_ct_renewal` 的标准科目名称为“专线/其他产品续签成本”，无法仅凭字段判断业务属性。金额大于 0 时必须由用户逐项目选择“属于专线，计入”或“属于其他产品，不计入”，未选择时阻断生成。

模板的“立项金额”沿用 `{IT_INVESTMENT}` 占位符；甄选结果生成时以批次立项金额覆盖该变量，不改变其他模板对 `IT_INVESTMENT` 的原语义。

## 公共字段冲突

阻断冲突：中选合作伙伴、甄选方式、甄选规则、客户支付方式、合作伙伴支付方式。任一字段存在多个非空值时必须先统一项目资料或拆分签批表。

可覆盖冲突：甄选范围、行业/场景、标准方案说明。用户明确确认后，整批统一使用当前签批表页面填写的字段值。

批次名称默认取“首项目名称去除末尾 `项目` / `ICT项目` + 等N个ICT项目”，用户可编辑。项目背景和其他批次级描述使用当前签批表页面内容。

## 正式生成门槛

生成前同时满足：

1. 批量模式至少选择 2 个项目，所有项目数据已完整加载；
2. A-E 每张表均能为每个所选项目生成至少一条有效行；
3. 各项目均通过既有财务 0 容差校验；
4. 各项目具备项目净现值率、项目毛利率和 IT 净现值率；
5. 阻断公共字段无冲突，可覆盖冲突已确认；
6. 所有混合续签成本已归类；
7. 批次立项金额严格小于 500000 元（不含税）。

达到或超过 50 万元时只阻断该“50万以下”模板，不自动改写项目数据或选择其他模板。

## 测试

- `npm run test:selection-batch --prefix src-ui`：验证五表顺序、甄选限价、投入/收入独立汇总、立项金额、续签归类、冲突检测和默认批次名称。
- `cargo test selection_result_docx_fills_batch_rows_and_approval_amount -- --nocapture`：以真实签批表模板生成两项目文档，验证五表增行、合计、立项金额和占位符清理。
- `npm run build --prefix src-ui`：TypeScript 与生产构建校验。
