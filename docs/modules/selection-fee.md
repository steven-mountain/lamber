# 采购甄选费测算模块设计

## 费率与税基（2026-09-09）

报价、限价、浮动均含税。`benefit/selection_fee.rs` 是正反算唯一档位事实源，固定 6% 除税查档；Tauri 命令仍为 `calculate_selection_fee` / `reverse_calculate_selection_fee`。

| 不含税中选金额 | 不含税服务费 |
| --- | --- |
| (0, 12100] | 100.00 |
| (12100, 48500) | × 0.825% |
| [48500, 100000] | 400.00 |
| (100000, 1000000] | × 0.809985% |
| > 1000000 | 8099.85 |

报价 0 对应服务费 0。先对不含税服务费 half-up 到分，再乘 1.06 并 half-up 到分。报价除税不提前舍入。实际测算成本=含税报价+含税服务费；最高限价=实际测算成本+含税浮动。输入拒绝无效数字及超精度/范围，不降级为零。

返回值用 `selection_fee_excl` / `selection_fee_incl` 显式区分税基，兼容键 `selection_fee` 仍指不含税，产品消费含税字段。`quote_excl` 是四位小数展示值，不参与二次计算。

反算边界全部由不含税档位与税率推导。各档内按整数分二分搜索，结果必须正算精确等于目标；10 万档跳变空档和其他逐分无解均明确报错，不返回近似报价。低档向下跳变可能产生多个报价，返回候选列表并明确当前采用较低报价；切回报价正算可指定具体候选。

## 状态与界面

独立 `useSelectionFeeCalculator` 拥有输入、锚点、目标科目、合并模式及派生结果。锚点 `quote | limit` 互斥：编辑报价固定报价，编辑限价固定限价，改浮动保持锚点。结果与输入键及恢复代次绑定，迟到请求不能覆盖新输入或新方案；等待、失败、空输入都不能使用旧结果写入。失败正文直接显示在面板。

恢复方案只恢复锚点输入与配置，由当前引擎重算辅助面板，不信任历史派生服务费。正式科目不自动重算、不迁移，只在用户点击写入后改变。

## 写入与持久化

全部投入科目仍由统一 `ICT_SUBJECT_DEFINITIONS` 分组显示。`中标服务费`不可同时作为目标；旧数据缺少目标或无效代码默认集成服务。目标必须按科目的**当前实际税率**判定为 6%，设备 13%、手改为 9% 的集成服务等均明确拒绝；提示说明既有选择/税率不符合新口径，不能静默过滤选项。

- 默认拆分：目标写入含税限价－含税服务费，中标服务费写入含税服务费。
- 勾选合并：目标写入全额含税限价，不提交中标服务费科目，已有值保持；界面明示需用户核对重复计入。不会自动清空已有金额。

两模式均复用 `normalizeTaxPairFromIncl`、原批量更新及科目付款计划同步，不绕过不可精确表示检查或0容差核验。智能反算同步辅助面板时，拆分按目标额－浮动回推报价；合并把目标额作为限价交给相同引擎反算，不复制费率。

`IctInput.selection_fee_merge_service?: boolean` 随方案保存至 lifecycle 工作副本及效益快照，缺省为拆分。其余 `selection_fee_*` 辅助元数据继续沿既有保存链路传递，`selection_fee_amount` 新保存值为含税。辅助字段本身不参与正式效益公式。

生成效益分析表仍将报价、浮动写入原 T26/T29；Excel 导入没有合并元数据，按缺省拆分恢复。没有数据迁移。历史项目需以最新算法重新计算，金额是否变化取决于档位、锚点与舍入；只有用户点击写入会改变正式科目。
