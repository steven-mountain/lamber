# 仓库提交与隐私边界

提交包含源码、构建清单、测试和脱敏设计/验收记录。API key、认证文件、本机配置、数据库、工作区、业务附件、生成文档和编译缓存不得进入 Git。忽略规则也适用于嵌套工作区；已被跟踪的本地文件需要从索引移除，仅增加忽略规则不够。

代码通过仓库位置、应用数据目录 API、环境变量或系统临时目录解析路径，不硬编码开发者的个人目录。仓库文档以仓库根目录为相对路径基准，外部应用数据和临时位置用 `<app-data>`、`<temp>` 等占位符。历史验收记录中的路径可脱敏，业务结论不变。验证脚本对外输出文件名，避免将本机完整路径写入新证据。安全测试可以使用不包含真实身份的合成绝对路径验证隔离与路径拒绝行为。

推送前检查完整暂存区，不能只扫描工作区或新增行：核对文件清单、二进制附件、个人路径和联系方式；以本机实际密钥做不回显值的精确比对，并用 Gitleaks 检查暂存区导出的文件树及即将推送的历史。扫描日志和真实配置保留在仓库外。提交者使用 GitHub noreply 隐私邮箱。

`.gitleaks.toml` 继承全部默认检测规则，仅对业务字段标识 `approval_amount_below_500k` 和指定历史证据文件中五个经源码核对的 SHA-256 值做精确例外。不得整文件跳过验证材料，也不得把未知密钥作为误报放行。TypeScript 配置允许 JSONC 注释，与标准 JSON 数据分开校验。

源码推送与应用发布、业务验收分开。D 的金额变更仍保留独立验收；图片能力仅包含展示、分析和用户确认替换，明确不包含 AI 修图。清理当前文件不会删除远端历史中的旧内容；历史改写与强制推送必须另行明确授权。
