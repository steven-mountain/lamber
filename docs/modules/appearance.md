# 外观设置与视觉设计系统 (Appearance Module)

本模块记录 Lamber 仓库前端外观体系的设计规范、功能实现以及后续扩展规则。

## 1. 视觉系统基准 (Phase 1)
Lamber 采用 **“建筑账本 (The Architectural Ledger)”** 创意方向，旨在呈现清晰、稳重、可信赖的业务视觉。

### 1.1 设计 Token 与 CSS 变量
核心颜色变量采用 HSL 分量形式存储在 `:root` 中，以便进行动态色值微调和不透明度混合。例如：
* `--primary`: `221 83% 53%` (对应 Tailwind `bg-primary`)
* `--background`: `210 40% 98%` (底色)
* `--card`: `0 0% 100%` (卡片表面)
* `--border`: `214 32% 91%` (常规边界)
* 状态颜色：`--success`、`--warning`、`--destructive` (与主品牌色隔离)。

### 1.2 "无边框" 规则 (No-Line Rule)
* 避免使用传统高对比度的 `1px` 深色实线框作为区块分割；
* 优先使用浅色色差背景（如在 `bg-background` 中嵌套 `bg-card` 或 `bg-muted/30` 容器）来实现视觉分区；
* 配合微妙投影（`shadow-sm` / `shadow-md`）突出悬浮面板或活动状态。

### 1.3 字体与财务对齐
* **财务字体规范**：所有涉及金额、比例、测算数值的单元格和展示字段，必须使用 `.numeric-value` 类，应用以下样式以确保数值垂直对齐：
  ```css
  font-variant-numeric: tabular-nums;
  ```
* **字号计算**：所有字体大小均与 CSS 变量 `--font-scale` 绑定计算，支持等比伸缩而不破坏排版。

## 2. 主题切换与设置中心 (Phase 2)
通过 `SettingsView.tsx` 统一控制整站主题和页面排版参数。

### 2.1 预设主题 (Presets)
系统提供 5 套内置浅色主题预设：
1. **Lamber 默认 (`lamber`)**：皇家蓝强调色 + 浅蓝灰底色。
2. **石墨灰 (`graphite`)**：木炭黑强调色 + 纯灰底色。
3. **海军蓝 (`navy`)**：深蓝强调色 + 蓝灰底色。
4. **森林绿 (`forest`)**：林地绿强调色 + 浅绿灰底色。
5. **暖石色 (`warmStone`)**：暖泥土强调色 + 暖灰底色。

### 2.2 统一深色基底 (Dark Mode Base)
* 所有主题预设在深色模式下共享一个深灰色/深蓝色基底（`#0f172a` / `#1e293b`），配合细微的 Preset 特征色点缀；
* Graphite 使用纯中性深灰，Navy 使用偏蓝深灰，Forest 使用偏绿深灰，WarmStone 使用偏暖褐深灰，维持各自视觉特质。

### 2.3 字号缩放与版面密度
* **字号缩放比例**：紧凑 (`0.93`)、标准 (`1.00`)、舒适 (`1.08`)、大字号 (`1.16`)，行高按比例缩放防止重叠。
* **间距密度定义**：
  * 紧凑 (`compact`)：卡片 Padding `1rem`，组件高度 `2rem`，表格 Vertical Padding `0.5rem`。
  * 标准 (`standard`)：卡片 Padding `1.5rem`，组件高度 `2.25rem`，表格 Vertical Padding `0.75rem`。
  * 宽松 (`comfortable`)：卡片 Padding `2rem`，组件高度 `2.5rem`，表格 Vertical Padding `1rem`。

### 2.4 持久化与跨窗口同步
* **Early Hydration**：偏好存在 `localStorage` 中，并在 `main.tsx` 加载 React 之前同步解析注入，彻底解决页面加载时的色彩闪烁（Flash）。
* **跨窗口广播**： workbench 主窗口与 AI 顾问独立悬浮窗口之间通过 Tauri 事件 `appearance-settings-updated` 实现多窗口样式实时双向同步。

### 2.5 AI 助手入口显示偏好
* `AppearanceSettings.aiLauncherVisible` 控制主窗口右下角 AI 助手悬浮入口是否渲染，偏好仅保存在 `localStorage` 的 `lamber_appearance_settings` 中。
* 默认值为 `false`：主窗口默认隐藏 AI 悬浮图标；用户可在“外观设置中心 / AI 助手入口”中重新开启。
* 该偏好只控制入口按钮显示，不修改 AI 上下文构建、AI 对话窗口能力、项目状态、模板状态或任何业务数据写入路径。
* 悬浮入口拖拽位置使用外层 `translate3d(...)` 更新，拖动过程中通过 `requestAnimationFrame` 直接刷新 DOM transform；React 状态和 `lamber_ai_launcher_position` 只在拖动结束、取消或窗口 resize 时同步。
* 外层定位元素不得使用 `transition-all`、`left/top` 连续更新或其他会对位置变化做动画插值的样式；hover/active 动画应放在内部视觉层，避免拖拽时产生鼠标滞后。

### 2.6 AI 多会话工作区

* AI 窗口宽屏采用约 `216px` 的 Session Sidebar 与自适应 Chat Area；Sidebar 使用 `bg-muted/40`，active Session 使用 `bg-card + shadow-sm`，依靠 surface shift 而非硬分割线建立层级。
* 当前项目会话优先分组展示，其他项目和通用会话进入次级分组；项目归属只使用低干扰 caption，不与会话标题争夺视觉层级。
* 小于 `680px` 时 Session Sidebar 必须转为覆盖式抽屉，禁止继续压缩消息和输入区；Chat 顶栏必须保留明确的展开入口。
* AI 会话工作区继续消费全局 semantic token、圆角、字体缩放和 dark mode，不允许增加独立配色、任意 HEX 背景或大面积高饱和色块。
* 详细状态与执行边界见 [ai-session-workspace.md](./ai-session-workspace.md)。

### 2.7 AI 模型与服务设置

* AI 运行配置使用设置中心内的独立卡片，沿用 `Card`、`Input`、语义状态色与低对比 surface；不新增高饱和背景或传统分隔线。
* 模型、API Key、baseURL 同屏设置。密钥输入不回显已保存值，只显示“已保存”状态，并提供显式清除动作。
* 视觉模型在候选项中标明图片能力；非视觉模型的说明必须明确其能力边界，不得暗示图片会被自动降级为文字。
* 非 DeepSeek 官方端点显示 warning surface，说明当前兼容性验证结论；提示不应阻止保存合法的 `http(s)` 地址。
* 保存成功或失败使用紧邻表单的语义反馈，保存成功同时说明 dsh 已停止、下一条消息将按新配置重启。
* 阶段 1 在设置卡提供联调台入口，用于无环境变量的装机 gate；该入口需明确标注为联调用途，不能被描述为最终产品 Chat。

## 3. 高级自定义与对比度无障碍防护 (Phase 3)
为用户自定义色值提供符合 WCAG 标准的无障碍保护。

### 3.1 自定义强调色与 HSL 转换
* 用户可提供 HEX 格式颜色，由 `deriveAccentTokens.ts` 解析转换为 HSL 变量写入 Root，覆盖 `--primary`、`--primary-foreground`、`--primary-soft`、`--ring`、`--accent` 及其前景色。

### 3.2 WCAG 对比度实时检测与亮度纠偏
* 在标准对比度模式下，强调色需与背景保持至少 **4.5:1** 的对比度；
* 实时校验：如果对比度不达标，系统将自动降低（浅色模式下）或提高（深色模式下）强调色的 HSL 亮度分量 `L`，并推导安全的替代色，展示对比度修正警告。
* 动态前景色：前景色 `--primary-foreground` 自动计算（在轻 slate `#f8fafc` 和深 slate `#0f172a` 之间选择），确保文字高 legible。

### 3.3 高对比度 Preference overrides
* 当 `contrastPreference === "high"` 时，强制应用纯黑/纯白画布、强化边框可见度，且强调色对比度检测阈值提升至 strict **7.0:1**（WCAG AAA 级）。

## 4. 后续开发与扩展约束 (Constraints)
1. **应用级偏好定位**：外观主题设置属于应用偏好，**严禁**写入 workspace project SQLite 数据库表格或项目本地 `project.json` 中，仅可保存在应用 `localStorage` 里。
2. **状态色隔离**：`success` (绿)、`warning` (黄/橙)、`destructive` (红) 的语义配色是具备业务含义的逻辑状态，**严禁**被用户自定义的主品牌强调色覆盖，防止业务语义重叠。
3. **响应式及多窗口一致**：所有新增的弹窗、副视图、Tauri Webview 窗口必须在 mount 时订阅 appearance store 事件监听，确保样式同步，且新组件必须消费 semantic HSL 主题变量，不得直接硬编码 HEX 颜色。
4. **AI 入口隔离**：AI 悬浮入口显示偏好只属于应用 UI 偏好，不得写入 workspace 数据库，也不得作为 AI 能否读取或写入业务数据的权限判断。

## 5. 智算测算工作台

* 智算测算采用“单一编辑画布 + 固定只读结论侧栏”，不得增加右侧编辑抽屉或固定中间栏压缩计算项编辑空间。
* 顶部状态使用低饱和 surface chips；主色仅用于当前 Tab、主操作、展开控制和重点状态。
* 参数区采用分组折叠容器。规模、定价、投入默认展开，运营、财务默认显示单行摘要，减少首屏纵向负担。
* 参数区不再使用关键/已修改/敏感筛选隐藏参数；默认展示全部参数，顶部只保留搜索和“展开全部 / 折叠全部”控制。
* 展开分组内使用 `repeat(auto-fill, minmax(240px, 1fr))` 自适应网格，宽屏展示三列，窄屏自然降为单列。
* 参数卡使用低对比度值卡，不使用多类型彩色左边框；仅展开分组容器使用主色细强调，避免多个色彩层级互相干扰。
* 参数卡名称独占标题行可用宽度，状态标记和说明/设置图标置于名称下方，避免长名称被操作控件挤压。
* 参数类别标题提供低干扰拖拽手柄、数量、折叠、类别内新增和次级菜单；清空搜索后允许自由排序，搜索结果视图隐藏拖拽能力。
* 参数说明在当前参数卡内按需展开，不保留固定说明侧栏，避免挤压自适应卡片网格。
* 参数区不设置“更多参数 / 高级参数”分隔；全部参数由类别、展开状态和搜索共同组织。
* 参数区顶部使用低饱和 `primary-soft` 项目周期摘要卡，突出 1-10 年周期编辑及其与 ICT 的同步关系，但不引入高饱和大面积背景。
* 收入/成本项默认使用一致的摘要卡，收入使用低饱和绿/蓝语义，成本使用低饱和橙/红语义；默认层只显示金额、占比、同步、计划与公式摘要。
* 计算项向下展开后仅提供“项目编辑 / 计算公式 / 资金计划”三个 Tab；ICT 科目下拉属于项目编辑，不建立独立 ICT Tab。
* 效益结论侧栏宽度约 `292px`，只读分组展示结论、核心金额、收益指标、关键构成和输出操作；窄屏转为主区域下方展示，不得产生页面级横向溢出。
* 数值、金额、比例继续使用 tabular numbers；引用、字段 key 和同步诊断属于次级信息，不得与业务结论争夺视觉层级。
* ICT 同步明细等宽表格使用固定列宽和横向滚动承载长财务字段；“来源项”“状态”等诊断列必须保留可读宽度，避免单字换行拉高整行。

## 6. 文档模板表单组织

* 一键生成文档中的重点模板页使用共享 `TemplateDocumentLayout` 骨架：顶部模板标题、横向 Tab、右侧完成度提示、当前 Tab 字段区和固定底部效益评估栏。
* 当前启用共享骨架的模板为《会审纪要》《ICT项目立项签批表》《ICT项目需求导入表》；其他模板仍沿用原普通表单卡片，避免误改不确定业务页面。
* 模板分组导航必须放在内容区顶部，不在左侧新增步骤导航，避免与测算流程导航和模板列表导航叠加。
* Tab 仅作为展示分组：字段名、`gen_*` key、保存状态、常用内容、AI 图片分析、询价生成、图片上传和文档生成数据流均沿用原逻辑。
* 《ICT项目立项签批表》内容字段较少，采用“签批信息 / 生成确认”两段式导航；项目背景、服务内容、商务条款、立项与采购选项在“签批信息”页内用低对比子模块分组展示，避免过度拆分。
* 《ICT项目需求导入表》采用“需求信息 / 生成确认”两段式导航；需求单位、客户确认、服务内容、商务模式、实施风险和附件材料在“需求信息”页内按业务段落分组展示，减少少量字段分散到多个 Tab 的切换成本。
* 技术方案可行性清单、中台能力调用、询价过程、公示/招标材料、信息安全、截图附件等子模块使用低对比 surface 卡片收纳，降低长表单信息密度。
* 共享底部效益评估栏展示 NPV、净现值率、毛利率、动态回收期、IRR 和生成按钮；主内容需预留底部空间避免遮挡。
* ICT 生命周期顶部工作区信息可使用 header 右侧按钮/下拉承载，保留打开目录与修改目录能力，不再为该页面单独占用一整行。

## 7. dsh 产品聊天（阶段 3B 默认切换）

* 聊天默认使用 dsh，模型设置入口复用设置中心卡片，限制高度并滚动，保留输入区空间。
* 2026-09-07 已删除临时回退与返回新版入口。模型设置仅保留 dsh 配置；历史记录仍可读，旧历史的新会话过渡通过项目选择完成。
* 无 ACP 映射的旧历史在输入区上方提示“发送时会新建会话”，避免把仅本机可见的历史误认为已传给新版模型。
* 工具步骤使用可折叠的低饱和 surface，显示工具名称、状态及按需展开的参数/结果，不用边框和彩色面板分割。
* 普通模型明确显示不支持图片并引导改模型；视觉模型启用附件入口，不用文字替代图片上传。
* 浮窗复用现有审批对话框，不另设计一套授权交互；同一审批只投递一个承载窗口。

## 8. 需求表聊天附件补齐

- 缺项卡片用bg-muted/50与bg-card区分目标和槽位，沿用语义色及标准圆角。
- 明示项目、模板、附件名称和“按已保存表单检查”；文件选择/粘贴由用户发起，模型不触发入库。
- 预览复用ImageAttachmentPreview；关闭预览与删除资产明确区分，失败提示紧邻卡片。
- 回执显示实际路径，生成中延后追加系统回执，避免干扰流式回答。

### 会话项目选择（路线图②）

未设置会话权限时显示 `bg-muted/50` 内嵌选择卡片；仅列出当前工作区的已有项目，配套明确的“通用聊天”入口。完成选择后开放输入，顶栏显示后端绑定项目名称或“通用聊天 · 仅聚合只读”（③更新口径）。历史记录留在原会话；未绑定历史进入同一选择流程后新建身份。使用既有圆角、语义文字和表面色差，不引入新边框或独立配色。

## 长文本审批（2026-09-07）

审批以项目、表单、字段、实际写入位置表达意图；当前值与可编辑新值并列，窄屏纵向排列，明确区分覆盖与填空。
正文保留换行，独立滚动区与固定操作区让长文可读；灰阶 surface 区分层级，沿用 Inter 字体、ROUND_FOUR 圆角及 tabular-nums。
修改后显示“修改后批准”并可展开模型原文；提交失败保留弹窗和错误，不吞掉待审核内容。
审核最长10分钟，队列共用后端绝对截止时间，不因排队重新计时；到期始终拒绝。详情见 [ai-approval-review.md](./ai-approval-review.md)。

### 审批窗口与模板冲突提示（阶段 B）

审批请求只由指定窗口订阅，完成通知同步清除其他窗口同 requestId 队列，避免残留的可点击旧决定。模板文本冲突使用既有低饱和 surface 提示，保留草稿查看区，并明确“放弃本页未保存编辑，载入最新内容”；未解决时阻止旧副本保存和生成。

## ICT 项目方案栏（2026-09-07）

- 项目信息与项目操作使用纵向分区，按实际内容容器宽度换行，不能仅凭视口 lg 断点强制并列；测算流程栏及逆算侧栏会进一步压缩内容宽度。
- 预设操作组件输出多个按钮，调用处须显式分组；不得依赖组件数量推断 DOM 网格列数。保存与另存为同组，组内也允许窄容器换行。
- 名称占有独立可用空间，项目/客户长名称可断行；状态徽标保持整词；阶段入口可换行，更多方案下拉限宽，当前方案名允许截断并通过 title 查看。
- 项目操作按钮及关联项目选择器统一 h-9；阶段按钮及更多方案选择器使用 h-8 级别，显式覆盖全局 select h-11，避免视觉错位。
- 自由测算复用分区与换行原则。外层及阶段分组用 surface 与投影区分，不增加传统分隔边框。

### AI 浮窗位置恢复（2026-09-07）

窗口打开由 `services/aiAssistantWindow.ts` 统一负责。新建窗口先隐藏并等待原生created/error，现有窗口恢复最小化，两条路径都在show/focus前读取当前显示器workArea，校验位置和尺寸；无效坐标移回主窗口所在显示器，必要时缩至可用范围。有效负坐标外接屏不因坐标小于零而重置。

`lib/aiWindowPlacement.ts` 统一使用物理像素。`lamber_ai_window_position` v2保存物理位置；历史无版本记录按逻辑像素兼容换算，随后执行同一可见性核验。不能仅依赖创建选项preventOverflow或清除缓存来处理屏幕断开/缩放变化。
